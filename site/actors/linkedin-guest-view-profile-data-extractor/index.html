    LinkedIn Guest-View Profile Data Extractor is an Apify Actor published by Vexaloom Labs. It accepts 8 input fields, none of them required at the top level. Each result can carry up to 30 declared fields, including name, headline, location, profileUrl, followersCount and connectionsText. It costs $0.99 per 1,000 results on Apify's Free plan and $0.49 on the Business plan.

    Run it

    Set APIFY_TOKEN to your Apify API token, then run the Actor with the input below (default run with company enrichment). Each run is billed to your Apify account. The export tutorial turns the results into a CSV file or an Excel workbook.

    Keep the first run small: maxSearchResults (default 25, maximum 100) caps how many results a run collects, and so what it costs.

    What it costs

    LinkedIn Guest-View Profile Data Extractor uses pay-per-event pricing: a fee for each result saved to the dataset, plus a start fee per run. Paid Apify plans pay less per result. The start fee is charged once per GB of run memory (at least once); the default run uses 4 GB, so a run starts with 4 start events, as the run totals include. You also pay Apify platform usage (compute and proxy) for the run, which these totals do not include.

    Input reference

    All 8 fields of the published input schema, in the publisher's order. No field is required at the top level, but the README can describe conditions. Download the input schema as JSON.

    Input fields in the published schema
    FieldTypeDescription
    profileUrlsProfile URLsarrayLinkedIn profile URLs (https://linkedin.com/in/username) or bare usernames. Full URLs, usernames, 'in/username' shorthand and regional subdomains are all accepted. Optional when searchNames is provided.Example ["https://www.linkedin.com/in/williamhgates"]
    searchNamesSearch NamesarrayOptional search-by-name mode: full names (e.g. "Satya Nadella") to find on LinkedIn's public people directory. Every discovered profile is then scraped through the same pipeline and appears with its own searchQuery field. Combine with profileUrls or use alone.
    searchCompanySearch: Current Company FilterstringOptional. When searching by name, keep only candidates whose directory card lists this company (case-insensitive substring).
    searchLocationSearch: Location FilterstringOptional. When searching by name, keep only candidates whose directory card lists this location (case-insensitive substring).
    maxSearchResultsSearch: Max ResultsintegerUpper bound on profiles discovered and scraped in search-by-name mode.Default 25; Allowed 1 to 100
    enrichCompanyEnrich Current CompanybooleanFetch the current employer's own public LinkedIn company page for extra detail (employee count, size, industry, website, headquarters, logo, specialties, founded year, followers, description). Uses a free public mirror, so it adds no proxy cost. Cached per company within a run.Default true
    includeStatusRowsInclude Status RowsbooleanAdd one structured status row when a run returns no profiles or only some of the requested profiles. Turn off if you want the dataset to contain profile records only.Default true
    cookiesCookies (optional)stringOptional and entirely unnecessary for the cookieless data. Supply your own LinkedIn session cookies (browser-export JSON, a JSON array of {name,value}, or a raw Cookie header) to additionally fill fields LinkedIn withholds from logged-out visitors — the real headline, exact connection count, and the full Experience list with titles and dates. Use cookie as an alias accepted for compatibility. Never required; leave empty for the standard cookieless run.
