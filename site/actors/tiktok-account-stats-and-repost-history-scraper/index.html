    TikTok Account Stats & Repost History Scraper is an Apify Actor published by Vexaloom Labs. It accepts 13 input fields, none of them required at the top level. Each result can carry up to 7 declared fields, including rowType, username, displayName, followerCount, videoCount and profileUrl. It costs $0.99 per 1,000 results on Apify's Free plan and $0.49 on the Business plan.

    Run it

    Set APIFY_TOKEN to your Apify API token, then run the Actor with the input below (stats snapshot for a watchlist). Each run is billed to your Apify account. The export tutorial turns the results into a CSV file or an Excel workbook.

    Keep the first run small: maxPostsPerProfile (default 30, maximum 500) and maxItems (default 0, maximum 100000) cap how many results a run collects, and so what it costs.

    What it costs

    TikTok Account Stats & Repost History Scraper uses pay-per-event pricing: a fee for each result saved to the dataset, plus a start fee per run. Paid Apify plans pay less per result. The start fee is charged once per GB of run memory (at least once); the default run uses 4 GB, so a run starts with 4 start events, as the run totals include. You also pay Apify platform usage (compute and proxy) for the run, which these totals do not include.

    Input reference

    All 13 fields of the published input schema, in the publisher's order. No field is required at the top level, but the README can describe conditions. Download the input schema as JSON.

    Input fields in the published schema
    FieldTypeDescription
    usernamesTikTok UsernamesarrayTikTok usernames to look up (with or without @). You can mix usernames and profile URLs, and list as many as you need in one run.Example ["natgeo"]
    profileUrlsProfile URLsarrayFull TikTok profile URLs (e.g. https://www.tiktok.com/@khaby.lame). Can be used instead of or together with Usernames.
    contentTypesWhat to collect per accountarrayChoose which rows to emit for every account. 'profile' = account stats and metadata, 'videos' = the account's posts, 'reposts' = content the account re-shared, 'playlists' = the account's playlists (names, covers, video counts).Default ["profile", "videos"]; Example ["profile", "videos", "reposts"]; Allowed profile, videos, reposts, playlists
    playlistUrlsPlaylist URLs (optional)arrayFull playlist URLs (e.g. https://www.tiktok.com/@natgeo/playlist/wildlife-7509464647364283178) to collect the videos inside those playlists. Independent of Usernames.
    maxPostsPerProfileMax Post Rows per ProfileintegerMaximum number of post rows per account, combined across videos and reposts. 0 skips post collection entirely (useful for a fast stats-only run). Playlist rows are not counted.Default 30; Example 10; Allowed 0 to 500
    maxItemsMax Post Rows per RunintegerGlobal cap on post rows for the whole run across all accounts (0 = no limit). Profile and playlist rows are not counted.Default 0; Allowed 0 to 100000
    includeProfileInfoInclude Profile InfobooleanWhen off, no profile rows are written even if 'profile' is selected above; only post rows are produced.Default true
    oldestPostDateOnly Posts From This Date (optional)stringSkip posts published before this date (UTC). Format: YYYY-MM-DD, e.g. 2026-01-01. Leave empty to collect the newest posts with no lower bound.Default ""
    newestPostDateOnly Posts Up To This Date (optional)stringSkip posts published after this date (UTC). Format: YYYY-MM-DD, e.g. 2026-01-01. Leave empty to start from each account's most recent post.Default ""
    includeLiveStatusInclude Live StatusbooleanAdds isLive and, when the account is live, the live room title, start time and viewer count to the profile row. Emitted only when TikTok reports the account's live status.Default true
    computedStatsAdd Derived StatisticsbooleanAdds averagePlays, medianPlays and postsPerWeek to the profile row, computed over the videos fetched for that account in this run (the window is the returned set, not the full history).Default false
    onlyNewVideosOnly New Videos (monitoring)booleanWhen on, each account emits only the videos posted since the previous run of that same account. The newest video seen is remembered between runs in the actor's named key-value store, so scheduling the actor turns it into a new-video monitor. The first run for an account returns all videos up to Max Post Rows per Profile and seeds the state. Reposts and playlists are not filtered. If the stored state is ever lost, the next run behaves like a first run.Default false
    pinnedFirstShow Pinned Videos FirstbooleanWhen on, videos the account pinned to the top of its profile (TikTok's pinned posts) are emitted before the rest of the post rows collected in this run. Pinned videos also carry isPinned: true.Default false
