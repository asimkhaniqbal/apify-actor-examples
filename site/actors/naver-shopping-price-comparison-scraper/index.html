    Naver Shopping Price Comparison Scraper is an Apify Actor published by Vexaloom Labs. It accepts 6 input fields, none of them required at the top level. Each result can carry up to 10 declared fields, including productName, price, originalPrice, discountPercent, reviewScore and reviewCount. It costs $0.99 per 1,000 results on Apify's Free plan and $0.49 on the Business plan.

    What it does

    The full README, with every mode, example and answer the publisher documents, is on the Apify Store page. Its sections: “What this actor does”, “Services and data source”, “How it works”, “Output per product”, “Input” and “Use cases”.

    What you get

    Run it

    Set APIFY_TOKEN to your Apify API token, then run the Actor with the input below (three keywords, ads off). Each run is billed to your Apify account. The export tutorial turns the results into a CSV file or an Excel workbook.

    What it costs

    Naver Shopping Price Comparison Scraper uses pay-per-event pricing: a fee for each result saved to the dataset, plus a start fee per run. Paid Apify plans pay less per result. The start fee is charged once per GB of run memory (at least once); the default run uses 4 GB, so a run starts with 4 start events, as the run totals include. You also pay Apify platform usage (compute and proxy) for the run, which these totals do not include.

    Input reference

    All 6 fields of the published input schema, in the publisher's order. No field is required at the top level, but the README can describe conditions. Download the input schema as JSON.

    Input fields in the published schema
    FieldTypeDescription
    searchQueriesSearch keywordsarrayOne Naver Shopping search per keyword, in Korean or English. Each keyword returns up to 90 product cards, including ads. Leave empty only when an old task supplies a single keyword.Default []; Example ["스마트폰"]
    includeAdsInclude paid adsbooleanKeep sponsored product cards in the results. Ads take a large share of the up to 90 cards, so ads-off runs return the organic subset. Every record carries isAd.Default true; Example false
    minPriceMinimum price (KRW)integerDrop fetched products cheaper than this price in Korean Won. Applied after collection, to the products this run fetched.Allowed 0 to 100000000
    maxPriceMaximum price (KRW)integerDrop fetched products more expensive than this price in Korean Won. Applied after collection, to the products this run fetched.Allowed 0 to 100000000
    sortSort productsstringOrder the products this run fetched. Naver's mobile page does not accept a server-side sort, so this is a local sort, not a re-query.Default "relevance"; Allowed relevance, priceLow, priceHigh, reviews
    maxItemsMax productsintegerTotal products to save across all keywords, after ad and price filtering (1–1000). The source still caps each keyword at 90 cards.Default 100; Example 2; Allowed 1 to 1000
