Wikipedia Article Lookup by URL or Keyword

Fetch structured data for Wikipedia articles by URL or keyword search, in any language edition - summary, description, categories, images, and last-edit timestamp.

Wikipedia Article Lookup by URL or Keyword is an Apify Actor published by Vexaloom Labs. It accepts 16 input fields, none of them required at the top level. Its build declares a results dataset with 1 view. Runs happen on Apify, where the Store page lists the current price.

Open on ApifyGitHub source

Input schema

Input fields, types, required flags, descriptions, defaults, and prefills come from the published definition. Prefill examples are distinct from defaults.

FieldTypeRequiredDescription
articleUrlsarrayoptionalWikipedia article URLs to look up. Works with desktop, mobile and index.php URLs, and with any language edition. Example: https://en.wikipedia.org/wiki/Albert_Einstein
articleTitlesarrayoptionalExact article titles to look up in the selected language edition. Spaces or underscores are both accepted; redirects are followed. Example: Albert Einstein.
searchQueriesarrayoptionalKeywords to search with Wikipedia's full-text search. Returns the top-ranked matching articles per query.

FieldTypeRequiredDescription
articleUrlsarrayoptionalWikipedia article URLs to look up. Works with desktop, mobile and index.php URLs, and with any language edition. Example: https://en.wikipedia.org/wiki/Albert_Einstein
articleTitlesarrayoptionalExact article titles to look up in the selected language edition. Spaces or underscores are both accepted; redirects are followed. Example: Albert Einstein.
searchQueriesarrayoptionalKeywords to search with Wikipedia's full-text search. Returns the top-ranked matching articles per query.
maxArticlesPerQueryintegeroptionalMaximum search results to fetch for each query (1-500).
categoryNamesarrayoptionalWikipedia category names to browse, with or without the Category: prefix. Each member page becomes an article record.
maxArticlesPerCategoryintegeroptionalMaximum category members to fetch for each category (1-500).
languagestringoptionalWikipedia language edition for titles, searches and categories. URL lookups use the language in each URL instead.
maxItemsintegeroptionalHard cap on total article records emitted across all modes.
includeFullContentbooleanoptionalAdd the complete article body as plain text in fullText (not only the lead summary).
includeSectionsbooleanoptionalAdd the article's heading outline (title, level, anchor) in sections.
includeExternalLinksbooleanoptionalAdd the outbound external URLs cited or listed by the article in externalLinks.
includeLinksbooleanoptionalAdd the titles of other Wikipedia articles linked from the article in links.
includeReferencesbooleanoptionalAdd the number of inline citations in referencesCount.
includePageviewsbooleanoptionalAdd a pageview series and total in pageviews, from Wikimedia's pageview API.
pageviewsGranularitystringoptionalMonthly or daily pageview points. Used when Include pageviews is on.
pageviewsPeriodsintegeroptionalNumber of pageview periods to return: 1-12 months for monthly, or 1-365 days for daily.

Wikipedia Article Lookup by URL or Keyword

Wikipedia exposes far more than an article's opening paragraph: a one-line description, the categories it belongs to, its images, its place on the map, the Wikidata entity behind it, its edit history, and the language editions it exists in. This actor collects that structure for articles you name by URL, exact title or keyword search — or for every page inside a Wikipedia category — and can add the full plain-text body, section outline, links, citation count, and pageview history.

Everything comes from Wikimedia's public APIs. There is no login, token, cookie or proxy setup.

Ways to feed it

  • Paste URLs — desktop, mobile and index.php links all work, in any language edition. A URL's own domain decides its language.
  • Name exact titles — one title per list item, in the language edition you choose. Redirects are followed.
  • Search by keyword — Wikipedia's ranked full-text search, with the result snippet and rank attached to each record.
  • Browse a category — every page in a category (or several) becomes an article lookup.
  • Mix any of the above in one run. An article reached through several URLs, titles or searches is emitted once, with those inputs recorded as provenance.

FAQ

Do I need a key, login or proxy? No. All four lookup paths work anonymously from an Apify container.

Which language editions are supported? The 374 language codes Wikimedia lists, from en and de to zh-min-nan and simple. Canonical and legacy codes map to the same edition. URL lookups take the edition from the URL; the language field applies to titles, searches and categories.

Why is summary shorter than fullText? summary is the lead section. fullText is the whole article and is only requested when you switch it on.

Can I get pageviews for any period? Yes — up to 12 monthly points or 365 daily points. The current partial month is included; daily data ends at the most recent day Wikimedia has published (usually two days ago).

What are the hard limits? Search returns at most 500 hits per query; categories, external links, internal links and language links are capped at 500 values per article, and images at 50. referencesCount counts inline citations but does not return the citation text. Rendered HTML and infobox key/value extraction are intentionally not part of this actor.

What happens to missing or non-article pages? Pages the API reports as missing are skipped and logged. Disambiguation pages are returned with isDisambiguation: true so you can filter them downstream.

Does it work with old tasks created before the revamp? Yes. The four original inputs keep their names, and earlier alias keys are mapped in code.

Use it as an API (server mode)

Need one answer right away instead of a batch job? Send the input as an HTTP request and the results come back in the response. There's no run to start and poll.

curl -H "Authorization: Bearer $APIFY_TOKEN" \
  "https://vexaloom-labs--wikipedia-article-lookup-by-url-or-keyword.apify.actor/?articleTitles=Ada%20Lovelace"

Or POST the same input as JSON:

curl -X POST -H "Authorization: Bearer $APIFY_TOKEN" -H "Content-Type: application/json" \
  -d '{"articleTitles": ["Ada Lovelace"]}' \
  "https://vexaloom-labs--wikipedia-article-lookup-by-url-or-keyword.apify.actor/"
  • The fields are the same as in the input above. With GET, repeat a parameter once for each value in a list.
  • You get back a JSON array with the same records a normal run saves. They're saved to the run's dataset too.
  • Each request is capped at 20 results and 4 minutes. For bigger jobs, start a normal run.
  • The request runs in your own Apify account at the Actor's normal price (a start fee plus a price per result). The server shuts down after a minute with no requests.
  • The Server tab on this page lists every parameter and lets you try a request from your browser.
