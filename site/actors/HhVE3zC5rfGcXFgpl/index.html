Pinterest Pins, Profiles, Boards and Ideas Collector

Pinterest exposes a lot of structured public data beyond what a page shows at first glance: media variants, creator and board context, engagement counts, product metadata and provenance. This actor collects that data from Pins, profiles, boards, board sections, comments, idea topics and search results in one dataset, without a Pinterest login or user-supplied credentials.

What this actor does

  • Fourteen collection modes: Auto-detect, Pin detail, comments, Pin search, video search, people search, board search, profile detail, a creator's Pins, a creator's boards, board detail, board Pins (including board sections), board sections, and idea-topic Pins.
  • Direct-first transport: public profile, board, Pin and comment resources are called directly. Search tries the same direct path first, then falls back through the free automatic proxy pool when Pinterest returns an empty success envelope.
  • Cursor pagination: follows Pinterest's bookmarks for searches, creator feeds, board feeds and comments, with repeated-cursor and duplicate guards.
  • Opaque-ID honesty: some feeds return encrypted e1_... Pin IDs. Those rows are kept as list records with idIsEncrypted: true, detailAvailable: false and no invented Pin URL.
  • Source-backed filters: saves, creator followers, verification, destination link, image-only, promoted Pins and shoppable Pins. A filter drops a row only when Pinterest supplies the value it needs.
  • Truthful counting: every emitted record, including comments and board sections, counts toward maxItems. Missing values are omitted; explicit zeroes and false values are preserved.
  • Provenance: every row says where it came from (sourceType, sourceValue, position), plus the search query, seed and numeric-ID recovery source when those apply.

Output per record

Every row carries record_type/recordType (pin, profile, board, boardSection or comment), source_url/sourceUrl, scraped_at/scrapedAt, sourceType, sourceValue and position. Search rows also carry query; every row carries seed. Rows recovered from a creator feed carry numericIdSource.

Pin fields

Pin rows can include id/pinId, idIsEncrypted, detailAvailable, commentsAvailable, url/pinUrl (numeric Pins only), title, description, altText, created_at/createdAt, dominant_color, link/linkUrl, linkDomain, domain, contentCategory, canonicalUrl, canonicalPinId, canonicalPinUrl, images, imageUrl, imageVariants, imageWidth, imageHeight, video_url/videoUrl, videoVariants, videoDurationMs, videoDurationSec, videoThumbnailUrl, is_video/isVideo, mediaType, pinFormat, storyPinId, storyPages, mediaMethod, seoTitle, seoDescription, seoUrl, mobileLinkUrl, trackedLinkUrl, utmLinkUrl, creator, creatorId, creatorUsername, creatorName, creatorUrl, creatorFollowerCount, originalCreator, originalCreatorUrl, board, boardId, boardName, boardUrl, boardOwnerUsername, boardCoverImageUrl, boardPinCount, boardFollowerCount, boardSectionCount, boardCollaboratorCount, boardPrivacy, boardCreatedAt, saves/save_count, commentCount/comment_count, repinCount, shareCount, reactionCounts/reaction_counts, reactionCount, likeCount/like_count, isPromoted, commentsDisabled, commentsEligible, isEligibleForImageDownload, isEligibleForProduct, isOutOfStock, isStaleProduct, isUnsafeForComments, isDownstreamPromotion, shouldMute, richMetadata, product, productPrice/priceValue, productCurrency/priceCurrency, productMerchant, productAvailability, isShoppable, shoppingFlags, hashtags, sourceType, ideaId, ideaSlug and sourceIdeaUrl.

imageVariants and videoVariants keep Pinterest's own size names. Each entry can carry url, width, height, duration and thumbnailUrl. The primary imageUrl uses the stable 736x variant when Pinterest supplies it. Story Pin pages can carry pageId, layout and blocks with type, text, images and videos.

Profile, board and section fields

Profile rows include type, id/profileId, username, full_name/fullName, bio, location, createdAt, follower_count/followerCount, following_count/followingCount, pin_count/pinCount, board_count/boardCount, monthlyViews, avatarUrls, avatarUrl, image_url, website_url/websiteUrl, domainUrl, profile_url/profileUrl, isPrivate, isPartner, isVerifiedMerchant, isDomainVerified, isTastemaker, isAdsOnlyProfile, isAdsOnly and isVerified.

Board rows include type, id/boardId, name/boardName, description, url/boardUrl, pin_count/pinCount, follower_count/followerCount, sectionCount, collaboratorCount, privacy, coverImageUrl, owner_username/ownerUsername, isCollaborative and followedByMe.

Board-section rows use record_type: boardSection and include id/sectionId, title/sectionTitle, slug/sectionSlug, pin_count/sectionPinCount, url/sectionUrl, plus the parent board's boardId, boardName and boardUrl.

Comment fields

Comment rows include id, text, created_at, type, node_id, like_count, reaction_counts, reaction_by_me, helpful_count, marked_helpful_by_me, reply_count, is_edited, is_highlighted_by_pin_owner, is_translatable, tags, tagged_users, media, author_name, author_username, author_id, author_first_name, author_image, author_image_medium, author_node_id, author_is_private_profile, pin_id and pin_url.

Missing fields are omitted. A published 0 or false stays in the row; an absent field means Pinterest did not publish it to the anonymous response.

Use cases

  • Keyword and video research with rich Pin cards, media variants and destination links.
  • Creator and board directories with published follower, Pin and section counts.
  • Full board or board-section exports for content audits and mood-board analysis.
  • Public comment and engagement collection for moderation or market research.
  • Idea-topic discovery for trend and category research.
  • Recurring jobs that need stable provenance and no login.

Limitations and hard limits

  • Opaque Pin IDs: search and board feeds can return encrypted IDs that do not open. Those rows keep every list field but no url; detail and comment collection requires a numeric ID.
  • Search engagement: Pinterest usually omits save and comment counts from search cards, so those fields are absent there. Detail mode fills them for numeric Pins.
  • Board depth and detail: a board's public feed may end before maxItems because Pinterest caps what it exposes. The feed can also return lightweight list rows (ID, image and media only) for some boards, so title, creator and engagement fields may be absent there. In-feed story modules such as "Related Interests" are not Pins and are never emitted as Pin rows.
  • Idea topics: the idea page exposes a list-only feed capped at roughly 17 Pins and has no pagination.
  • Related Pins: the related-Pin feed returns zero rows from anonymous datacenter traffic, so it is not a shipped mode.
  • Comment replies: replies are not advertised as a mode; only the public top-level comment feed is collected.

FAQ

Do I need Pinterest cookies or an API key?

No. Every mode works anonymously. Cookies supplied by an older saved task are ignored, and no private data is accessed.

Why is a field missing from one row?

Pinterest does not publish every field for every Pin, account, board or media type. Missing values are omitted instead of guessed; a published 0 or false is kept.

Why does a search return records without save or comment counts?

Search cards generally omit engagement counts. Use pinDetail or enrichDetails for numeric Pins when those fields matter.

What happens when a Pin has an encrypted ID?

The row is emitted as a list record with its title, description, media, creator and board where Pinterest supplies them. It has idIsEncrypted: true, detailAvailable: false, commentsAvailable: false and no Pin URL.

Can I collect a board section directly?

Yes. Paste a three-part section link into boardUrls with boardPins, or let auto route it. Use boardSections when you want the section list itself.

Are comments included in the item limit?

Yes. Comment and board-section rows count toward maxItems exactly like Pin, profile and board rows.

Why did a run return no records?

The actor fails with a clear status message instead of reporting a silent success. The RUN_SUMMARY in the key-value store lists raw rows, accepted rows, rejected rows and the rejection reason, such as an unsupported URL, an opaque detail request, a private page or a filter that removed every row.

Does the actor use a proxy?

Public traffic is tried directly first. When a request is blocked or returns an empty success envelope, the actor automatically falls back to a free proxy pool. You do not need to configure a proxy, though an optional override is available.

Is this affiliated with Pinterest?

No. This is an independent tool that reads public Pinterest pages and is not affiliated with or endorsed by Pinterest.
