    Search & URL Markdown Extractor for LLMs is an Apify Actor published by Vexaloom Labs. It accepts 25 input fields, none of them required at the top level. Each result can carry up to 13 declared fields, including url, title, description, wordCount, httpStatusCode and loadedTime. It costs $0.99 per 1,000 results on Apify's Free plan and $0.49 on the Business plan.

    What it does

    The full README, with every mode, example and answer the publisher documents, is on the Apify Store page. Its sections: “What this actor does”, “Output per page”, “Input”, “Use cases” and “FAQ”.

    What you get

    The Actor saves one record per result to an Apify dataset. Its build declares 13 fields in 1 dataset view, and the README documents 9 more. Fields without a value can be left out of a record.

    Run it

    Set APIFY_TOKEN to your Apify API token, then run the Actor with the input below (google a question and keep only substantial pages). Each run is billed to your Apify account. The export tutorial turns the results into a CSV file or an Excel workbook.

    Keep the first run small: maxResults (default 3, maximum 250) caps how many results a run collects, and so what it costs.

    What it costs

    Search & URL Markdown Extractor for LLMs uses pay-per-event pricing: a fee for each result saved to the dataset, plus a start fee per run. Paid Apify plans pay less per result. The start fee is charged once per GB of run memory (at least once); the default run uses 4 GB, so a run starts with 4 start events, as the run totals include. You also pay Apify platform usage (compute and proxy) for the run, which these totals do not include.

    Input reference

    All 25 fields of the published input schema, in the publisher's order. No field is required at the top level, but the README can describe conditions. Download the input schema as JSON.

    Input fields in the published schema
    FieldTypeDescription
    querySearch query (or one URL)stringWhat to look up, or a single web page URL to read. Examples: vector database comparison, https://en.wikipedia.org/wiki/Retrieval-augmented_generation. When startUrls or queries are also set, everything is processed in one run.Default "what is retrieval augmented generation"
    queriesMore search queriesarrayAdditional queries for batch research runs. Each query is searched and its top results are fetched. A query that is itself a URL is fetched directly.Default []
    startUrlsStart URLsarrayPages to read directly. With maxCrawlDepth above 0, the actor walks links found on these pages within the same website instead.Default []
    searchEngineSearch enginestringWhich search engine to use. Automatic tries Google first and silently falls back to Bing, then DuckDuckGo when an engine is blocked — recommended.Default "auto"; Allowed auto, google, bing, duckduckgo
    searchLanguageSearch languagestringLanguage for search results. Automatic lets each engine choose based on the query.Default "auto"; Allowed auto, en, de, fr, es, it, pt, nl and 25 more
    searchCountrySearch countrystringCountry bias for search results. Automatic means no country bias.Default "auto"; Allowed auto, ad, ae, af, ag, ai, al, am and 242 more
    maxResultsMax search results per queryintegerHow many top organic results to fetch and emit for each search query. Values above 10 need multiple search-result pages (slower). With Emit results for pages that could not be fetched on, each of the requested results yields one record — a page record when the fetch succeeds, or a metadata record with fetchError when it does not.Default 3; Allowed 1 to 250
    maxItemsMax pages per runintegerOverall cap on how many pages the run may emit across all queries, URLs, and crawled pages. 0 means no global cap.Default 0; Allowed 0 to 10000
    outputFormatsOutput formatsarrayWhich representations to include per page, in any combination. Links adds every link found on the page as structured {url, text} pairs.Default ["markdown"]; Allowed markdown, text, html, links
    removeElementsCssSelectorRemove elements (CSS selector)stringComma-separated CSS selectors removed before extraction (navigation, footers, ads, cookie bars). Set a non-matching selector such as dummy_keep_everything to keep everything.Default "nav, footer, aside, script, style, .ad, .advertisement, ...
    keepElementsCssSelectorKeep only elements (CSS selector)arrayWhen set, only content inside these selectors is kept — everything else is dropped before extraction.Default []
    htmlTransformerMain content extractionstringReadable content finds the article body and drops navigation and boilerplate. None keeps the full cleaned page.Default "readable-text"; Allowed none, readable-text
