Quora Keyword Search & Author Discovery Scraper

Search Quora by keyword or scrape visibly accessible question, answer, profile, topic, Space, and Post URLs directly, with filters for promoted cards, AI-labeled answers, unanswered questions, and author discovery across your results.

maxScrollAttemptsintegeroptionalBound the number of browser pagination/scroll attempts per question page. This is capped at 20 to control cost and runaway pages.
maxLoadMoreAttemptsintegeroptionalBound clicks on exact visible search continuation controls independently from scrolling. No click is attempted by default.

includeAnswersbooleanoptionalExpand and emit answer records for question pages.
includeMediabooleanoptionalExtract image/video URLs from visible question, answer, and post content. External links are controlled independently by includeOutboundLinks.

includeAnswerHtmlbooleanoptionalInclude the rendered HTML of answer content. Disable to reduce dataset size.

includeQuestionTopicsbooleanoptionalRetain explicit topic links associated with question rows. Disable to reduce question-context payload; this does not affect answer or post traversal.
maxQuestionTopicsintegeroptionalBound retained explicit topic names/URLs on question rows. Zero preserves all observed topic links; positive values emit question_topics_scraped and question_topics_limit_reached diagnostics.
topicFilterarrayoptionalFor question and search-result rows, retain only rows with an exact explicitly observed topic label or topic URL matching one of these terms. Unknown topic evidence is excluded and counted; this is local payload filtering, not a server-side Quora filter.
includeSpaceSettingsbooleanoptionalOpt in to explicitly labeled Space settings/content-permission evidence for Space rows; missing settings remain unknown and admin-only queues are not scraped.
includeQuestionDetailsbooleanoptionalRetain rendered question description/body text on question rows. Disable to reduce payload while preserving question identity, metrics, answer/post traversal, and status envelopes.
includeQuestionHtmlbooleanoptionalRetain bounded rendered HTML from the question scope after nested answer regions are removed.

includeCommentsbooleanoptionalExtract only comments rendered in visible answer comment-content nodes; hidden comments are not inferred.
includePostCommentsbooleanoptionalFor standalone post URLs, retain only comments inside an explicitly labeled Top/Most helpful/Popular collection as top_comments. Ordinary comments, votes, and position never qualify.
maxCommentsPerPostintegeroptionalBound the visible post-comment nodes inspected when includePostComments is enabled; this is not a complete comment-history guarantee.
includeEngagementBreakdownbooleanoptionalOpt in to explicitly labeled answer-scoped upvote/reaction items in nested answer rows. Comment controls and icons are never decomposed.
includePostAuthorContextbooleanoptionalOpt in to explicitly labeled About, Education, and Joined/Member since values inside the owning standalone-post author scope; no profile navigation or inference is performed.
maxPostAuthorContextItemsintegeroptionalMaximum explicitly labeled active Space links retained per standalone-post author when includePostAuthorContext is enabled; zero emits none.
maxCommentsPerAnswerintegeroptionalMaximum visible comments extracted from each answer when comments are enabled.
maxReplyExpandAttemptsintegeroptionalBound clicks on clearly labeled visible reply/comment expansion controls per question page.
maxCommentDepthintegeroptionalMaximum explicit comment nesting depth retained from answer pages. Root comments are depth 0; deeper comments are omitted and marked with comment_depth_limit_reached. The maxDepth alias is accepted for compatibility.

usernamesarrayoptionalQuora profile usernames/slugs (with or without a leading @ or trailing slash). Normalized to https://www.quora.com/profile/{slug} and merged into the direct-URL queue; also seeds author-discovery and post-discovery when relevant.

maxItemsPerTabintegeroptionalIndependent cap on profile_activity rows per tab (answers/questions/posts), in addition to maxProfileActivityItems. Zero means unlimited.
maxDetailItemsintegeroptionalWhen scrapeDepth=detail, bounded number of profile_activity items opened individually for detail_text/detail_title extraction. Zero disables detail expansion.
includeUnchangedbooleanoptionalWhen onlyNewItems is set, also retain change_type=unchanged rows instead of dropping them.
maxAuthorsintegeroptionalMaximum unique discovered author rows to emit, independent of maxItems. Requires resultTypes to include author.
maxSourcePagesintegeroptionalMaximum author-discovery source pages (search/question/answer/topic/Space/post/profile) whose already-scraped rows are scanned for author evidence.
maxEvidencePerAuthorintegeroptionalMaximum evidence_urls/evidence_question_urls/evidence_answer_urls/evidence_answer_previews entries retained per discovered author.

includeRelatedContentbooleanoptionalOpt in to an explicit 'related/attached content' region scoped to one answer or post card.

Distinct from maxItemsPerSource, which caps already-scraped rows rather than discovery candidates. Direct standalone post URLs given via directUrls/startUrls are always scraped and are unaffected by this setting.
includeGraphEdgesbooleanoptionalCompatibility alias for includeEntityGraph. The canonical includeEntityGraph takes precedence when both are supplied.
includeTopicQuestionsbooleanoptionalEmit visible topic question links as topic_question rows.
maxTopicQuestionsintegeroptionalBound topic_question rows emitted per topic page. Zero means unlimited.
includeTopicPostsbooleanoptionalEmit explicitly linked standalone Posts from a topic page as topic_post rows.

includeRelatedTopicsbooleanoptionalEmit visibly linked related topics as topic_related rows.
maxRelatedTopicsintegeroptionalBound topic_related rows emitted per topic page. Zero means unlimited.
includeAnswerPreviewbooleanoptionalOpt in to bounded, already-rendered answer-preview evidence on question/search_result cards, without navigating to the full answer page.
maxAnswerPreviewsintegeroptionalBound answer_preview_* entries retained per question/search_result card.
minAnswerPreviewUpvotesintegeroptionalMinimum typed upvote threshold an answer preview must meet to be retained. Fails closed: previews with unknown upvotes are excluded once this is positive.
cookiesarrayoptionalOptional authenticated browser cookies. Use only for content you are authorized to view; cookies are stored as secret input and are never logged.
cookieStringstringoptionalOptional browser-exported name=value; name2=value2 header. Parsed locally into authorized session cookies; the raw header is never emitted or logged.
proxyConfigurationobjectoptionalProxy settings. Quora's anti-bot layer challenges the shared datacenter/AUTO proxy pool on a large fraction of requests (cloud-measured ~33% success), so Residential proxy is the default and prefill here (cloud-measured ~96%+ success). Leave this untouched for reliable results.

Quora Keyword Search & Author Discovery Scraper

Find Quora pages by keyword or scrape question, answer, profile, topic, Space, and standalone Post URLs directly. Drop AI-labeled answers, low-voted answers or already-answered questions before they're saved, filter native Quora search cards by type, date and promotion label, preview an answer's top votes without opening its full page, and list the authors that appear across a batch of pages with evidence of where they showed up.

What this actor does

  • Turns each keyword into a list of matching Quora pages (found through a web search restricted to quora.com) and scrapes every page it finds, up to maxResults per keyword
  • Reads native Quora search pages (quora.com/search?q=... URLs, or automatically when the web search finds nothing) as search_result cards, where the content-type, time, date-range, sort and promotion filters apply
  • Scrapes question, answer, profile, topic, Space, and standalone Post URLs directly, or Quora usernames
  • Optionally previews an answer's upvotes, views, and text on the question/search card itself, without opening the answer's own page
  • Can list the authors referenced across the pages a run scraped and emit one row per author with the pages they were found on as evidence
  • Extracts comments (including nested replies), profile activity, topic-related questions/posts, and a Post author's About/Education/Joined info; comment and topic-link rows need their type added to resultTypes
  • Optionally emits explicit relationship rows (entity_edge) between questions, answers, topics, and authors
  • Can re-scrape the same inputs later and tag each row new, changed, or unchanged against a saved state
  • Leaves empty fields out of each row rather than filling them with a guess

Output per record

Every row carries content_type, record_id, title/url/canonical_url, access_state, scrape_timestamp, requested_depth/observed_depth/detail_expansion_state, and (for search/direct-URL sources) source_url/source_query/matched_input.

Compact rows, crawl depth and session input

  • Smaller rows. outputFields is an optional allowlist applied after extraction, filtering and deduplication; an empty list returns the full row. Nested projection is supported with bounded dotted paths such as top_comments.comment_text or related_questions.title where that collection exists, and child identity/URL fields are kept. Identity, access/status, source and traversal fields always stay, and each row's output_projection says full or selected. includeFieldEvidence separately controls the field_sources/fields_present maps.
  • Crawl depth. scrapeDepth: "overview" reads only the initially rendered entity and skips answer, comment and profile-activity expansion; detail (default) runs the configured, capped traversal. Every row reports requested_depth, observed_depth and detail_expansion_state (not_requested, not_applicable, completed, bounded, blocked or failed). bounded means one of your caps was reached, not that Quora's whole history was read; a blocked page reports observed_depth: "status".
  • Author credentials. question_author_credentials, comment_author_credentials, post_author_credentials and author_credentials hold a credential or tagline only when Quora displays one inside that author's own block. They are never inferred from the text and are not a verification of expertise.
  • Session input. Pass structured cookies or the secret cookieString header (name=value; name2=value2). Structured cookies win on duplicate names, malformed pairs are ignored, and the raw header is never emitted or logged. Cookies and proxy settings are optional authorized inputs, not guaranteed access; a page that still shows a wall comes back as a typed status record.
  • Exact field names. Every output field this actor can emit is listed under Output per record above.

FAQ

Do I need a Quora account? No. Public pages are read without login. cookies/cookieString only extend access to content your account is already authorized to see; they are not a bypass guarantee.

What's "author-discovery mode" and how is it different from scraping a profile directly? Add author to resultTypes and the actor scans the pages your other inputs touched (search results, questions, answers), up to maxSourcePages, and emits one row per author found (up to maxAuthors), with evidence of where they appeared — useful when you don't already have a list of profile URLs.

What does includeAnswerPreview get me that a normal answer row doesn't? It reads the answer text/metrics that Quora already renders on the question or search card itself, without a separate page visit for that answer — handy for a quick scan across many questions.

Why do promoted/AI-answer filters sometimes keep cards I didn't expect? Both filters only act on an explicit, unambiguous label from Quora. A card or answer with no visible promotion or AI marker is left in rather than guessed at. The promotion filter also only applies to native Quora search cards, not to pages found by keyword.

Why did I get a status row instead of the entity I asked for? Quora showed a login wall, a Cloudflare challenge, or a removed/redirected page for that URL. The actor reports this as a status row instead of fabricating data. If three pages in a row come back blocked, the run stops processing the remaining URLs early, so expect fewer rows than inputs in that case.

How does keyword search pick pages? Each keyword is matched against quora.com pages through a web search, and up to maxResults of the pages found are opened and scraped in full (questions with their answers, profiles, and so on). Only when that finds nothing does the actor open Quora's own search page and return its cards as search_result rows. To always work with Quora's search cards, pass a https://www.quora.com/search?q=... URL in directUrls.

I turned on includeComments but got no comments. Why? comment isn't in the default resultTypes. Add it, and keep maxCommentsPerAnswer above 0.

What does the incremental re-scrape (onlyNewItems) compare? It hashes each entity's content and compares it to the previous run saved under stateStoreId, tagging rows new, changed, or unchanged. Status and manifest rows are always returned regardless of this setting.

Can I get a Space's or profile's full follower/member list? Count fields (follower_count, member_count) are returned when Quora displays them. Full identity lists for those collections aren't extracted by this actor.

Is this affiliated with Quora? No. This is an independent, third-party actor that reads Quora's public pages; it isn't affiliated with or endorsed by Quora, Inc.
