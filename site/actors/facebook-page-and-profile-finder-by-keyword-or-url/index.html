    Facebook Page & Profile Finder by Keyword or URL is an Apify Actor published by Vexaloom Labs. It accepts 16 input fields, and mode is required. Each result can carry up to 10 declared fields, including pageName, facebookUrl, entityType, verified, category and likes. It costs $0.99 per 1,000 results on Apify's Free plan and $0.49 on the Business plan.

    What it does

    Find Facebook Pages and public profiles by keyword, or read a list of Facebook URLs, IDs and handles. Each row can include the verified badge, category, phone, email, address, website, followers, ratings and reviews — plus optional Page Transparency and the latest visible post. No login, cookies or proxy setup.

    What this actor does

    • Two ways in: search Facebook by keyword, or read Pages/profiles you already have via URLs, profile.php?id=, /people/, /p/, numeric IDs and @handles.
    • Pages, profiles or both: one search can return Facebook Pages, public profiles, or a deduplicated mix of the two.
    • Deep, paginated results: follow Facebook's own result pages up to your maxResults limit, instead of stopping at a handful of search-engine hits.
    • Enrichment on demand: turn fetchPageDetails on for contact details, category, followers and ratings; add reviews, Page Transparency and the latest visible post when you need them.
    • Verified filtering: keep only Pages/profiles Facebook marks as verified with verifiedOnly.
    • Empty fields are omitted — the actor never fills a missing value with null, 0, or a placeholder.

    Use cases

    • Lead generation — find local businesses by keyword and collect the phone, email, address and website they publish.
    • Brand research — compare Pages in a category by followers, rating and verified status.
    • Competitor discovery — find every Page and public profile active around a keyword.
    • Bulk enrichment — feed a CRM export of URLs or numeric IDs and add contact and engagement data.
    • Reputation monitoring — pull published reviews and the latest post for a set of Pages.

    Questions

    Do I need a Facebook account or cookies?

    No. The actor reads only what Facebook serves to logged-out visitors. There is no login, cookie or API-key field.

    What is the difference between pages and people?

    pages returns business/brand/organization Pages; people returns public personal profiles; all returns both and removes duplicates.

    Why are some fields missing?

    The Page owner did not publish that information, or Facebook does not show it to logged-out visitors. The actor omits missing fields instead of guessing.

    Does the output include verified badges?

    Yes. verified is filled when Facebook shows the badge. Use verifiedOnly to keep only verified results.

    Why do image URLs stop working after a few days?

    Facebook serves signed CDN links that expire. Turn on rehostImages to copy profile and cover images into Apify storage; the originals remain in profilePictureUrlOriginal and coverPhotoUrlOriginal.

    Can I filter by category?

    Set categoryFilter to a word from the category, such as dentist, restaurant or clinic. It filters the enriched rows after page details are read; with fetchPageDetails off, rows without a category are dropped.

    Can I filter by city?

    Add a city or country to location or include it in the keyword (e.g. "dentist Berlin"). Facebook search is relevance-ranked, so this is a hint, not a strict filter. For Facebook’s Place filter on Pages, set locationUids to numeric Place IDs from facebook.com/places/<id>/ URLs. Multiple UIDs partition the search; nearby businesses can still appear.

    How many reviews and posts can I get?

    Up to 10 published reviews per Page and up to maxPosts recent timeline posts. Facebook does not expose the full review history or an unlimited timeline without a login.

    Can I use profile.php?id=, numeric IDs or handles?

    Yes. startUrls accepts full URLs, profile.php?id=…, /people/… and /p/…; startIds accepts numeric IDs and @handles.

    Is this affiliated with Facebook or Meta?

    No. This is an independent tool and is not affiliated with, endorsed by, or sponsored by Meta Platforms, Inc.

    Limits and notes

    Limits

    • maxResults is a ceiling. A single keyword query has its own finite index; add keywords, or use locationUids to partition a pages search across several Place IDs and merge the slices.
    • Facebook does not expose a server-side category filter to logged-out search. categoryFilter filters the enriched rows locally and requires fetchPageDetails.
    • Profile follower counts are returned only when Facebook shows them publicly; hidden/zero counts are omitted rather than guessed.
    • Exact likes in URL mode are filled when the page matches Meta's Ad Library typeahead; otherwise Facebook does not expose the count and it is omitted.
    • Facebook image URLs are signed and expire after about five days. Turn on rehostImages for durable profile/cover images; the original URLs are kept in profilePictureUrlOriginal and coverPhotoUrlOriginal.
    • locationUids partitions page searches by Facebook Place IDs; each row records its slice in searchLocationUid. Results can include nearby businesses, not only a strict city boundary.

    Use it as an API (server mode)

    Need one answer right away instead of a batch job? Send the input as an HTTP request and the results come back in the response. There's no run to start and poll.

    curl -H "Authorization: Bearer $APIFY_TOKEN" \
  "https://cjq13rwjckkpe9rcc.apify.actor/?mode=search&searchQueries=Starbucks&searchType=pages&maxResults=1&fetchPageDetails=false&includeReviews=false"

    Or POST the same input as JSON:

    curl -X POST -H "Authorization: Bearer $APIFY_TOKEN" -H "Content-Type: application/json" \
  -d '{"mode": "search", "searchQueries": ["Starbucks"], "searchType": "pages", "maxResults": 1, "fetchPageDetails": false, "includeReviews": false}' \
  "https://cjq13rwjckkpe9rcc.apify.actor/"
    • The fields are the same as in the input above. With GET, repeat a parameter once for each value in a list.
    • You get back a JSON array with the same records a normal run saves. They're saved to the run's dataset too.
    • Each request is capped at 60 results and 4 minutes. For bigger jobs, start a normal run.
    • The request runs in your own Apify account at the Actor's normal price (a start fee plus a price per result). The server shuts down after a minute with no requests.
    • The Server tab on this page lists every parameter and lets you try a request from your browser.
