Naver Web, Blog, Cafe & News Results Scraper

Run a query against Naver — South Korea's most-used search engine — and get back the same organic results a Korean user would see, from the web, blog, cafe, or news tab. Type a query in Korean or any other language and receive each result's title, link, domain, snippet, and source name as structured records.

What this actor does

  • Searches four Naver tabs: web, blog, cafe, and news results
  • Pages through up to 8 result pages per query (stopping earlier once two consecutive pages come back empty), up to your maxItems limit
  • Filters results by a keyword substring (checked against title, snippet, domain, and source name) or by domain
  • Adds mode-specific extras: post dates for blog/cafe results, and both the n.news.naver.com mirror link and press-profile link for news results
  • Omits any field that has no real value for a given result — you will not see nulls or empty strings

Output per result

  • title — result title
  • url / resultUrl — the result's destination link (same value under both keys)
  • domain — host extracted from the result URL
  • sourceName — publisher or site name as shown on the result
  • snippet — result description/preview text
  • date — post date or relative date (blog and cafe results only)
  • naverNewsUrl — link to the article on Naver's own news mirror (news results only, when available)
  • pressUrl — link to the publisher's press profile on Naver (news results only, when available)
  • serpUrl / sourceUrl — the search-results page this record was found on (same value under both keys)
  • recordType — searchResult for normal records, or error when the query itself failed (no silent drops)
  • scrapedAt — ISO 8601 timestamp of when the record was collected

If a query fails outright, you get a single error record instead: recordType: "error", errorType, message, sourceUrl (the page that failed), and scrapedAt.

Input

Field Type Default Description
mode string webSearch Which tab to search: webSearch, blogSearch, cafeSearch, or newsSearch
searchQuery string 비비바 Query in Korean or any other language
containsKeyword string – Only keep results whose title, snippet, domain, or source name contains this text
domain string – Only keep results from this domain (exact host or suffix, e.g. naver.com or blog.naver.com)
maxItems integer 20 Maximum records to return (1–500)

Example: web search for a Seoul restaurant

{
    "mode": "webSearch",
    "searchQuery": "서울 맛집",
    "maxItems": 30
}

Example: blog results restricted to one domain

{
    "mode": "blogSearch",
    "searchQuery": "비비바",
    "domain": "blog.naver.com",
    "maxItems": 10
}

Example: latest news coverage of a topic

{
    "mode": "newsSearch",
    "searchQuery": "서울 맛집",
    "maxItems": 20
}

Use cases

  • Local SEO research — see which sites and blogs rank for a Korean search term before investing content effort there
  • Brand monitoring — track news and blog coverage of a company or product name across Naver
  • Market research — compare how a topic is discussed across Naver's web, blog, and cafe communities
  • Content discovery — find blog and cafe posts about a niche topic for curation or outreach
  • News aggregation — pull the latest articles matching a keyword, with direct links to both the article and its publisher

FAQ

Do I need to type queries in Korean? No — any language works, though Naver's index is strongest for Korean-language content, which is where most useful results will come from.

What's the difference between blogSearch and cafeSearch? Naver currently serves the same merged blog-and-cafe result set for both tabs, so their output is often identical; both modes are kept because they mirror Naver's own tab structure, in case that changes.

Can I search Naver's image or "지식iN" (Kin) tabs? No — those tabs render their results with client-side JavaScript rather than in the page HTML, so they aren't exposed by this actor.

Why do some results have no date field? Only blog and cafe results carry a post date; web results don't have one, and even on blog/cafe tabs, a small number of posts don't expose a date Naver published.

What does a recordType: "error" record mean? It means the query itself failed to return a usable results page — you get an explicit error record instead of a silently empty dataset.

How many results can one query return? maxItems can be set up to 500, but the actor stops after 8 result pages per query, so in practice a single query typically returns well under that — fewer for niche queries, and even fewer once duplicate URLs are removed.

Is this affiliated with Naver? No. This is an independent actor that reads Naver's public search results pages; it is not endorsed by or affiliated with NAVER Corporation.
